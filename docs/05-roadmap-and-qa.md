# 开发路线与验收标准

## 1. 开发阶段

### 阶段一：数据冻结

- 从原型提取事件数据。
- 复核日期、北京时间、来源和置信度。
- 确定哪些事件可作为入坑日。
- 确定冠军统计范围和去重规则。

### 阶段二：领域逻辑

- 实现日期差计算。
- 实现入坑日、事件之间、指定日期三种关系。
- 实现对象筛选、年份筛选和事件类型筛选。
- 实现称号、特殊数字和倒计时。
- 为所有边界情况写测试。

### 阶段三：低保真交互

- 先实现角色选择、事件选择、结果预览三个页面。
- 先不做复杂动画和完整卡片装饰。
- 确认用户能在三次点击内进入事件列表。

### 阶段四：视觉设计

- 生成票据、记分牌、工作证和球台设计稿。
- 先确认设计稿，再生成无文字背景模板。
- 测试 1:1、3:4 和 9:16 的信息层级。

### 阶段五：平台与真机

- 接入保存图片、发布图文和带图评论。
- 验证存档恢复和失败降级。
- 在小红书容器中测试 iOS 和 Android。

## 2. 必须测试的逻辑

- 今天就是入坑日
- 跨年和闰年
- 未来日期禁止选择
- 起始日算第 0 天和第 1 天
- 只有年份的近似日期
- 北京时间口径
- 角色过滤和热门排序
- 个人、莎头、团体冠军不重复统计
- 特殊数字 511、1104、365、1000、5114
- 存档缺字段、旧版本和损坏数据

## 3. 必须测试的视觉行为

- 评论卡在 120×120 缩略图中仍能读出天数。
- 笔记卡在 240×320 缩略图中仍能看出称号和事件。
- 变量文字不覆盖模板装饰。
- 设计稿中的示例日期、姓名和标题全部被清除。
- 模板背景不透明。
- Canvas 导出尺寸准确。
- 低端设备首次出图不产生明显卡顿。

## 4. 发布前检查

- 无远程资源和运行时网络请求。
- 发布包只有一个入口页面。
- 图片和字体都在包内。
- 官方小工具能力检查通过。
- 事件数据截至日期显示在说明页和卡片底部。
- 统计口径说明可在工具内打开。
- 本地存档失败时仍能继续制作和导出。
